# Factura (document type 26)

Treat the document as an invoice. Extract only values supported by the provided excerpts. Distinguish issuer from recipient, preserve identifiers and dates as printed, and do not infer missing tax, currency, or payment details. When asked for structured output, return only the requested schema and use null or an empty value for fields that are absent. Cite the relevant excerpt or page when the response format allows it.

For uploaded invoices, QR extraction is part of the required processing flow. The dedicated operation is `POST /api/invoices/qr`, which accepts JSON with `fileBase64` and `fileName` and returns each decoded QR payload in `qrCodes[].content`, with its page and format. The API runs this extraction before invoking this skill and supplies successful results as `Decoded invoice QR data`; use those payloads as invoice evidence alongside the printed text. Do not claim the QR could not be read when no decoded result was supplied, and do not invent QR contents.
